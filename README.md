# 나만의 여행경로

구글 계정 연동 없이 Google Maps API 키만으로 여행 경로를 만드는 정적 웹페이지입니다. (`public/index.html` 단일 파일, 빌드 불필요)

## 구조
- `public/` : 화면(`index.html` 지도, `login.html` 로그인·가입, `admin.html` 회원 승인), `config.js`(지도 API 키)
- `src/worker.js` : 회원가입 / 로그인 / 관리자 승인 API + 정적 파일 접근 제어 (Cloudflare Workers + D1)
- `wrangler.jsonc` : 배포 설정 (D1 바인딩 `DB`, 관리자 이메일 `ADMIN_EMAIL`)

모든 요청은 Worker를 먼저 거치며, **로그인한 승인 사용자**에게만 지도 화면과 `config.js`(API 키)를 내려줍니다.

## 인증 흐름
1. 사용자가 이메일·비밀번호로 가입 → `pending`(승인 대기)
2. 관리자가 `/admin`에서 승인하면 로그인 가능 (거절·삭제 시 기존 로그인도 즉시 무효)
3. 비밀번호는 PBKDF2-SHA256(100,000회, 사용자별 salt)으로 해시해 저장, 세션은 HttpOnly 쿠키(30일)
4. 로그인 5회 실패 시 15분 제한, IP당 가입 시간당 5회 제한

## 화면 구성
- **일자별 일정**: 상단 `전체 / Day 1 / Day 2 …` 탭으로 하루씩 보거나 전체를 한 번에 봅니다. 일자마다 날짜(선택)를 넣으면 뒤 일자는 하루씩 이어서 채워집니다. `＋ 일자`로 일자를 추가하고, 장소 카드의 `Day N` 선택으로 다른 날로 옮길 수 있습니다.
- **이동 구간**: 장소 사이는 기본이 **직선**이고(“직선 1.9km ▾”), 구간 칩을 눌러 도보·대중교통·자동차·자전거 중 하나를 고르면 **그 구간만** 실제 경로와 소요시간으로 바뀝니다(주황 테두리로 표시, `기본값`으로 직선 복귀). 직선 구간은 경로 계산을 호출하지 않아 비용이 들지 않습니다. 일자 요약은 거리를 직선·경로 구간 합쳐 보여주고 이동시간은 이동수단을 정한 구간만 합산합니다(예: “3곳 · 4.0km(직선 1구간 포함) · 이동 32분(1구간)”). 설정한 구간의 경로는 구간마다 따로 계산하며 같은 구간·이동수단은 접속 중 메모리에 보관해 다시 계산하지 않습니다. 구글맵 링크는 정한 구간 수단이 모두 같으면 그 수단으로, 아니면 도보로 엽니다.
- 예전에 저장된 여행(전체 기본 이동수단이 모든 구간에 적용되던 방식)은 읽을 때 구간별 설정으로 자동 변환되어 기존 경로가 그대로 유지됩니다(데이터 `v:2`).
- **지도**: 보고 있는 일자의 경로를 주황색 굵은 선과 번호 핀으로 표시합니다(`전체` 보기에서는 일자별 색으로 구분).
- **여행 목록**: 카드형(일수·날짜 범위·장소 수·공동 편집 인원), `내 여행계획` / `공유받은 여행` 탭
- **카테고리 칩**: 장소를 추가할 때 구글이 알려주는 분류(예: 관광 명소, 라멘 전문점)를 한 번만 저장해 카드와 정보창에 칩으로 보여줍니다. 장소 ID(`placeId`)도 함께 저장합니다.
- **모바일 하단 탭**: 폭 760px 이하에서는 `여행 / 일정 / 지도 / 내 정보` 4개 화면으로 전환합니다. `일정` 화면은 위에서부터 제목·요약·일자 탭 → **고정 높이(190px) 미니 지도**(일정에 맞춰 표시, 누르면 지도 화면으로 확대) → 일정 목록 순서이며(장소 카드에는 주소 줄을 표시하지 않음), 장소 검색 대신 목록 **맨 아래 `＋ 장소 추가`** 버튼이 있어 누르면 `지도` 화면으로 이동합니다. `지도` 화면은 상단에 검색창과 일자 칩, 하단에 요약 카드(총 시간·거리, `일정 보기`, `구글맵`)를 보여주고, 일정에서 장소 이름을 누르면 지도 화면으로 이동합니다. `내 정보`에는 계정과 더보기 메뉴가 모입니다. 키보드가 올라오면 하단 탭은 숨겨집니다. PC 화면은 좌측 패널(상단 검색) + 지도 구조 그대로입니다.
- **헤더**: 큰 제목(26px) 아래에 한 줄로 “날짜 · 일수 · 장소 수”를 왼쪽에, “👥 N명과 공동 편집 · 저장 상태”를 오른쪽에 보여줍니다(총 2줄). 공유받은 여행의 `내 것으로 복사`는 더보기 메뉴에 있습니다.
- **편집 모드**: 일자 머리말 오른쪽의 `편집` 버튼을 누르면 장소 카드에 일자 이동·위아래·삭제 버튼이, 머리말 아래 줄에 `순서 최적화 · 역순 · 일자 삭제`가 나타납니다(`완료`로 닫음). 평소에는 카드와 머리말이 깔끔하게 보입니다.
- **하단 버튼**: `공유`, `구글맵에서 열기`(보고 있는 일자 기준)를 항상 노출하고 나머지는 `더보기`에 모았습니다.
- 데이터는 `여행 → 일자(days) → 장소(stops)` 구조입니다. 일자 도입 전에 저장된 여행은 자동으로 Day 1로 변환됩니다.
- 한도: 여행당 최대 30일, 200곳. 동시 편집 병합도 일자 단위로 동작합니다.

## 여행 저장 / 공유
- 여행은 **계정별로 자동 저장**됩니다(D1). 장소·제목·메모를 바꾸면 약 1초 뒤 저장되고, 다시 접속하면 마지막으로 연 여행이 열립니다.
- **📂 여행 목록**: `내 여행계획`(수정·공유·삭제)과 `공유받은 여행`(열람·복사·목록에서 제거) 두 탭
- **공유 = 공동 편집**: 승인된 사용자의 이메일로 공유하면 상대의 “공유받은 여행”에 나타나고, **함께 수정**할 수 있습니다(장소 추가·삭제·순서·메모·제목). 여행 삭제와 공유 관리는 만든 사람만 할 수 있고, 공유받은 사람은 “내 것으로 복사”나 “제거”도 할 수 있습니다.
- **동시 편집 처리**: 저장할 때 내가 본 버전을 함께 보내 서버가 최신 버전인지 확인합니다. 그 사이 다른 사람이 수정했다면 두 변경을 지점 단위로 합쳐서(내가 추가·삭제·수정한 것과 상대가 한 것) 다시 저장합니다. 같은 지점을 동시에 고치면 내 변경이 우선합니다. 공동 편집 중인 여행은 6초마다 상대의 변경을 확인해 자동 반영하며(입력 중에는 건너뜀), 탭이 보이는 동안에만 확인합니다.
- 예전에 이 브라우저에만 저장돼 있던 여행은 처음 접속할 때 내 계정으로 자동 가져옵니다.
- 한도: 계정당 여행 100개, 여행당 공유 50명
- 테이블(`trips`, `trip_shares`)은 첫 요청 때 자동 생성되므로 별도 마이그레이션이 필요 없습니다.

## Cloudflare 최초 설정
1. **D1**: `wrangler.jsonc`의 `d1_databases`는 `database_id` 없이 선언돼 있어 배포 시 자동 생성됩니다. 자동 생성이 안 되면 대시보드 Storage & Databases → D1에서 `tripoute-db`를 만들고 Worker의 Bindings에 변수명 `DB`로 연결하세요. 테이블은 첫 요청 때 자동 생성됩니다.
2. **관리자 설정 코드(비밀값)**: Worker → Settings → Variables and Secrets → Add → Type `Secret`, 이름 `ADMIN_SETUP_CODE`, 값은 직접 정한 긴 문자열
3. 배포 후 `/login` → 회원가입 탭 → 하단 "관리자 계정 만들기"를 눌러 `sundc753@gmail.com`, 비밀번호, 설정 코드를 입력해 관리자 계정을 만듭니다. (이후 설정 코드는 일반 가입에 영향을 주지 않습니다.)

## 로컬 실행
Node 설치 후 `npx wrangler dev` (로컬 D1이 자동 사용됩니다). 관리자 코드는 `.dev.vars` 파일에 `ADMIN_SETUP_CODE=...`로 둡니다(커밋 금지, `.gitignore`에 포함).

## Cloudflare 배포 (Git 연동, Workers Builds)
- Build command `exit 0`(또는 비움), Deploy command `npx wrangler deploy`
- `main`에 push하면 자동 배포됩니다.
- 발급된 `https://<이름>.<계정>.workers.dev` 주소를 API 키의 HTTP 리퍼러 제한에 `https://<주소>/*` 로 추가하세요.

## 새 버전 알림 (홈 화면 웹앱)
아이폰 홈 화면 웹앱은 한 번 열어 두면 배포가 바뀌어도 옛 화면이 남아 있습니다. 이를 위해
- Worker가 내려 주는 `index.html`에 화면 버전(정적 파일의 ETag, 없으면 내용 해시)을 `<meta name="app-version">`으로 박아 두고, `GET /api/version`(공개)으로 현재 버전을 알려줍니다.
- 앱은 열릴 때, 홈 화면에서 돌아올 때, 연결이 복구될 때, 그리고 5분마다 버전을 비교해 다르면 상단에 “새 버전이 나왔어요 · 지금 업데이트” 배너를 띄웁니다.
- `지금 업데이트`를 누르면 편집 중인 내용을 먼저 저장한 뒤 새로 불러옵니다. 저장이 끝나지 않았거나 실패한 상태면 새로 불러오지 않고 안내만 합니다. `나중에`를 누르면 닫히고 다음 확인 때 다시 알립니다.
- 로컬 개발 서버처럼 버전이 비어 있으면 확인을 건너뜁니다.

## 구글 지도 약관 유의사항
- 이 앱은 장소 이름·주소·좌표·분류를 여행 데이터로 DB에 저장합니다. 구글 지도 약관은 장소 ID(`placeId`) 외의 구글 콘텐츠 저장을 제한하고(좌표는 최대 30일), 지오코딩 주소는 최종 사용자별로 분리해 쓰도록 요구합니다. **지인 몇 명이 쓰는 개인·비상업 용도**를 전제로 한 설계이며, 가입을 공개로 열거나 사용자가 늘면 `placeId`만 저장하고 열 때마다 다시 불러오는 방식으로 바꿔야 합니다.
- 지도 왼쪽 아래 구글 로고와 오른쪽 아래 출처 표시는 가리지 않습니다. 장소 사진을 보여줄 때는 작성자를, 제3자 출처가 있으면 출처를 함께 표시합니다.
- 공개 서비스로 확대할 경우 공개 이용약관과 개인정보 처리방침 페이지가 필요합니다.

## API 키
`public/config.js`의 `TRIPOUTE_API_KEY`에 공용 키를 넣으면 승인된 사용자는 키 입력 없이 지도를 씁니다. 비워 두면 각자 키를 입력합니다.
